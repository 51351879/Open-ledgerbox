## 1. 背景

前身项目位于 `<前身项目目录>\`，是一套 Chase 对账单 PDF → CSV → 单文件 HTML Dashboard 的工具，运行约一年。表面完好：图表都能渲染，分类看起来很齐整，双语切换正常。

我们对它做了一次全面的专业审查（解析器正确性、前端逻辑、隐私、架构、以及自动化取数与开源可行性的外部调研）。结论是：**它是一个完成度不错的一次性分析产物，不是一个系统。**

---

## 2. 审查发现

### 2.1 最严重的：数字是错的

| 指标 | Dashboard 显示 | 真实值 |
|---|---|---|
| 总收入（13 个月） | $268,373.80 | **$58,725.12** |
| 净现金流 | +$209,436.28 | **−$212.40** |
| 储蓄率 | **78.0%** | **≈ 0%** |

**根因**（`parse_bank_statement.py:210-218`）：解析器用「块内第一个数字 = 金额，第二个 = 余额」的**文本顺序**启发式。Chase 存款行的金额列在 PDF 文本抽取时被甩到了页面另一个文本块，块内只剩余额 → **余额被当成了金额，真实金额被丢弃**。

**结构性证据（零例外）**：72 条 credit 全部 `balance` 为空，343 条 debit 全部有 `balance`。

**验证方法**：把 13 张账单上 Chase 自己印的 "Deposits and Additions" 相加 = $58,725.12；用余额链反推每笔存款金额再求和 = $58,725.12，**分毫不差**；重放整条链得到的最终余额 $288.71，与 2026-01 账单期末余额完全一致。

**为什么一年没被发现**：整条链路（PDF → CSV → JS → HTML → 决策）没有任何一个环节做过对账。而 Chase 每张账单都印着期初余额、期末余额、存入合计、取款合计——**一个 15 行的断言会在 13/13 张账单上失败，误差总和 $209,648.68**。

> 这个发现直接定义了新项目的核心原则：**对账是产品，解析器不是。**

### 2.2 解析器其他确认缺陷

| 位置 | 问题 |
|---|---|
| `extract_statement_period` | 账单月份取周期**起始**月。Chase 账期不从 1 号开始 → **`2025-06`、`2025-09`、`2025-12` 三个月在输出里根本不存在**，数据被并进前一个月。CSV 里只有 10 个 `statement_month` 却有 13 张账单 |
| `SKIP_PATTERNS` + `should_skip_line` | **子串**匹配，含 `"of"` `"SM"` `"Page"` `"Fees"`。已有一条真实交易的商户名被吃掉（描述只剩卡号片段）。`House of Sushi`、`Coffee Shop`（"Coffee" 内含 "of"）、`SMOG CHECK` 全部会中招。危险在于**金额保留、描述丢失**，所以看不出坏 |
| 金额正则 | `^-?\s*\d{1,3}(?:,\d{3})*(?:\.\d{2})?$` 接受无小数的裸整数。当前语料未触发（13 张账单都没有 Checks Paid 段），但支票号会被当金额——潜伏缺陷 |
| `process_directory` | 无去重。实测：把重复文件夹一起解析 → 830 条、去重后 415 条、**0 条被拦截**，总额精确翻倍 |
| 同上 | 中文路径触发 `UnicodeEncodeError`（cp1252），崩在读第一个 PDF 之前。**本次审查中现场复现** |
| 同上 | 单个 PDF 失败 → 整轮丢失；`save_to_csv` 用 `open(w)` 已截断旧文件 |
| `inject_data.py` | 破坏性单向注入，占位符**已被消耗**（当前 HTML 中 0 处）。再次运行什么都不改，却打印 "Successfully injected"。**数据刷新通道已经断了** |

**被证伪的假设**（记录下来避免重复怀疑）：符号处理没问题（Chase 确实在借记项输出 `-`，343 负 / 72 正 / 0 零，`type` 标签全对）；跨年逻辑在月度账期下写法是对的，只是从未被触发。

### 2.3 前端确认缺陷（14 项，摘录最重要的）

| 位置 | 问题 |
|---|---|
| `financial_dashboard.html:4496` | **内部转账计入收支**。支出侧 $58,937 里 $45,676（**77.5%**）是 Zelle / 信用卡还款 / 自己账户间转账；饼图里最大的"消费类别"是"转账 $34,107" |
| `:4385` | `"chase"` 是 `"Purchase"` 的子串。每条 Chase 描述都写着 `Card Purchase` → **68 笔 / $12,699 归入"银行费用"**（真实约 $577，虚高 23 倍）。它还成了静默兜底类，所以"其他"只有 $36.58，**看起来分类很完美** |
| `:4376` | 关键词裸写 `"76"`（加油站），匹配任意两位连号 → 16 笔 ACH/Zelle 被吸进"交通" |
| `:4655` | `detectAndRenderSubscriptions(data)` 的 **`data` 参数从未被使用**，返回硬编码 10 行表。上传任何数据都显示同样内容 |
| `:4693` | `annualExp = totalExp / 13 * 12` —— **13 写死** |
| `:4396`+`:4598` | `new Date("2025-01-02")` 按 UTC 解析、`.getDay()` 按本地读取 → 太平洋时区**星期分布整体错一天** |
| `:4493` vs `:4942` | 图表用 `date.substring(0,7)`、表格用 `statement_month`，415 行里 **83 行（20%）不一致** |
| `:4489`,`:4518` | "余额曲线"是从 0 累加的过滤后净额；解析出来的真实 `balance` 字段**全程没被读过一次** |
| `:9`,`:11` | Chart.js 走 CDN 且**完全未锁版本**、无 SRI、无 CSP → 离线白屏，且第三方脚本对 13 个月财务明细有完整同源访问权 |
| 全局 | 无 `localStorage`/`fetch`/任何持久化。语言、筛选、分类**刷新即丢**，且**无法手工修改单笔分类** |

**结构**：5,092 行单文件，其中 3,322 行（65%）是内联的交易数据；真正的应用逻辑约 838 行。`dashboard_data.js` 存在但**从未被引用**，是死副本。

### 2.4 隐私与开源阻断

- PDF 内含**完整账号、法定姓名、街道地址、邮编**；**26 个文件名全部带账号后四位**
- **10 个第三方真实姓名**（Zelle 对手方），每个关联具体日期与金额——他们从未同意被公开
- 每笔交易后的运行余额（343 行）、31 个 "City ST" 串（可定位住处/工作地/健身房/宠物医院）
- 交易数据在项目里有 **6 份副本**
- `:4385` 把**卡号后四位写成了分类关键词**，`:4374/4380/4382` 硬编码约 60 个本地商户名——**PII 烤进了逻辑里，删掉数据数组也带不走**
- 13 个 PDF 在两个文件夹里**逐字节完全相同**

## 3. 外部调研结论

### 3.1 自动化取数（决定：不实施，只写文档）

| 通道 | 结论 |
|---|---|
| Chase 消费者 API | **不存在。** `developer.chase.com` 整站锁在 JPMC 企业 SSO 后；JPM Payments 自助注册只给文档和 Mock，生产要走销售 4–6 周 KYC |
| OFX / Direct Connect | **已死。** `ofx.chase.com` 的 CNAME 目标 DNS 返回 NXDOMAIN，TCP 连不上。Chase 转 EWC+，token 存在聚合商处，**你拿不到可交给第三方客户端的凭据** |
| FDX | **卖规范不卖数据。** 2025-01-08 获 CFPB 承认（至 2030-01-08），个人会员 $99/年——但 FDX 不运营任何数据接口，且强制 FAPI 1.0 Advanced + mTLS + 动态客户端注册，**自然人不是可注册的 OAuth 客户端** |
| CFPB 1033 | **被法院禁止执行中**（2025-10-29，*Forcht Bank v. CFPB*），重新立法中 |
| **SimpleFIN Bridge** | ✅ **唯一个人可用**：$15/年，无需公司实体/KYB/销售/MSA。**协议只读**、token 存本机、可单方面吊销、覆盖 25 家机构。代价：Chase 凭据存在 **MX**；配额 24 次/天；单次最多跨 90 天；**首次同步历史深度未公布** |
| IBKR Flex Web Service | ✅ 券商侧唯一能无人值守跑 cron 的：自助开关、token 可设 6 小时–1 年、支持 IP 白名单、**含批次级成本基础** |
| Schwab | ⚠️ 个人开发者开放，但 **refresh token 7 天硬过期不可续**，必须每周手动浏览器登录 |
| Plaid / MX / Akoya / Finicity / Yodlee / GoCardless | ❌ 全部劝退（企业门槛、未公开定价、或已关闭新注册且只覆盖欧盟）|

### 3.2 MCP 安全（重要）

- **官方 Plaid MCP 硬编码 sandbox**，读不了真实账户（设计如此）
- 银行/券商官方 MCP **基本不存在**——`schwab`/`fidelity`/`InteractiveBrokers`/`SnapTrade`/`simplefin`/`ynab`/`actualbudget`/`beancount` 的 GitHub 组织 MCP 仓库搜索**全部返回 0**
- **最流行的两个社区服务器恰好最危险**：`code-rabi/interactive-brokers-mcp`（205★）索要 `IB_USERNAME` + `IB_PASSWORD_AUTH` + **`IB_TOTP_SECRET`**。**交出 TOTP 种子 = 2FA 变成装饰品**
- ⚠️ **2026 年没有官方 SQLite MCP**——官方仓库 `src/` 只剩 7 个（`everything`/`fetch`/`filesystem`/`git`/`memory`/`sequentialthinking`/`time`），SQLite 那个已归档，冻结约 14 个月

### 3.3 生态调研的关键结论

- **没有任何开源预算工具正确建模投资**。Actual 的券商账户是 off-budget，只记余额不记持仓；Firefly III 明确拒绝；Ghostfolio 做投资但**用 `Float` 存钱**。只有 Beancount 和 GnuCash 有真正的批次/成本基础模型
- **没有人解决 Chase PDF 摄入**。最好的 `monopoly`（191★）**只覆盖 Chase 信用卡**，不含支票账户。`ofxstatement` 约 56–75 个插件，**压倒性是欧洲的，没有 Chase 插件**
- 因此本项目填的是一个**真实存在的空白**，不是重复造轮子

## 4. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| 1 | **新建仓库，不重写 git 历史** | PII ≠ 凭据：密钥可轮换，交易史/账号/收入/住址**永久有效**。且重写历史抓不到改过名的路径、commit message 里的余额、**文件名本身的泄露**。新仓库是唯一能靠肉眼检查证明干净的方案 |
| 2 | **PyMuPDF → pdfplumber** | PyMuPDF 是 **AGPL-3.0，会传染整个项目**。pdfplumber 是 MIT，且提供逐词坐标——正是修复 2.1 那个 bug 的前提 |
| 3 | **复式记账** | 让"转账双重计数"在结构上不可能发生（见 2.3 第一行）。零和约束 = 永远在线的免费集成测试 |
| 4 | **整数最小单位存金额** | SQLite 官方：只有 `.00/.25/.50/.75` 能被浮点精确表示 |
| 5 | **SQLite 作真相，不用 DuckDB** | DuckDB 前向兼容只是 "best effort"，存储格式几乎每个小版本都动。做分析引擎正确，**做 20 年档案不合格** |
| 6 | **前端无构建链** | 2026 年的 Vite 配置在 2036 年大概率装不上，这与"长期复用"是同一件事。代价用强制模块化 + 400 行拆分红线对冲 |
| 7 | **数据默认放 XDG，不放仓库** | `.gitignore` 是缓解措施，**物理隔离才是控制措施**。加运行时守卫拒绝往含 `.git` 的目录写数据 |
| 8 | **只支持 Chase Checking** | 没有真实样本的银行，写出来的解析器等于幻觉——正是本项目要防的失败模式。其余走通用 CSV（P3）+ 插件 |
| 9 | **投资账户暂不做** | 同上，无真实券商样本。但 schema 保留 `lot`/`quantity_scaled`/`cost_*`/`corporate_action`，事后加这些列极痛 |
| 10 | **不实施自动化取数** | 只在 `docs/AUTOMATION.md` 交付调研成果与实现思路 |
| 11 | **AGPL-3.0-or-later + DCO** | 同类共识（Firefly III / Ghostfolio / Maybe）。**在第一个外部 PR 之前必须定死**——一旦以无 CLA 的 AGPL 接受外部贡献，永远无法在没有每位贡献者同意的情况下提供商业许可 |
| 12 | **提交文本层，不提交 PDF** | span JSON 可读、体积小，**且能有把握地脱敏——PDF 做不到**（内容流、内嵌字体、XMP 元数据、增量更新历史全都会漏） |

## 5. 已验证的技术事实

供实施时直接使用，不必重新验证：

| 事实 | 值 |
|---|---|
| Chase 对账单 `/Producer` | `OpenText Output Transformation Engine - 23.4.25` |
| 有无文本层 | **有**（首页 395 词）。**不需要 OCR** |
| 页数 | **不固定**：13 张里 10 张 4 页、3 张（2025-07/08/11）2 页 ~~每张 4 页~~（2026-08-03 实测更正） |
| 真实总入账（13 张自报合计） | **$58,725.12** |
| 真实总支出 | **−$58,937.52** |
| 真实净变动 | **−$212.40** |
| 2025-01 期初余额 | **$512.37** |
| 2026-01 期末余额 | **$288.71** |
| 借记链完整性 | 284 对连续行，**0 处断裂**（支出侧解析本身是对的） |
| 余额反推恢复法 | credit 的 `amount` 当余额，`bal_n − bal_{n−1}` 反推 → 13/13 张账单与 Chase 自报**分毫不差** |
| 各月存入合计 | **不写进仓库**（2026-08-04 决定）。单独看每一个都是聚合量，但十三个排在一起是一年收入的形状，其中一个月足以辨识。这一行原来列着真实值，`tests/test_money.py` 也复制了一份且不受 `LEDGERBOX_REAL_FIXTURES` 门控——即 CI 会跑它、公开仓库会带着它。逐月值仍由本机真实账单用例守着，见 `docs/STATUS.md` §6.5 |
